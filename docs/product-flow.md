# The FLOWSTATE customer flow

Start with **sign in → workspace → project → shared work → review/export**.

1. **Create a project.** Add a name and optional description. Keep the starter
   board for To do, In progress and Done, or uncheck it to begin without a board.
   Creation opens the project directly.
2. **Bring in teammates.** Owners/admins choose Invite teammates, enter an email
   and role, then copy the invitation link. Share it directly. Signup and sign-in
   return to the invitation. The invited email must match; links expire after 48 hours.
3. **Find the work.** Assigned tasks on the workspace home open the correct board
   and highlight the task. The same project tabs appear across boards, documents,
   uploaded-file details, code and settings.
4. **Create documents.** Search, filter and sort the Documents library. Choose
   Word, Excel, PowerPoint or PDF. Library update times include persisted shared
   edits. Returning from an editor goes back to the library.
5. **Handle existing files.** Files keeps original uploads. Available Office editing
   is labelled explicitly. Without that service, File details offers downloads
   and explains native document creation; unavailable conversion is not an active action.
6. **Build and review code.** Connect a repository, start a session, then open a
   text file. Opening it keeps the current folder. Suggest changes for owner/admin
   approval or edit the shared copy live. Public sessions download saved copies;
   authorized GitHub App sessions can create a branch and pull request.
7. **Share finished work.** Wait for the saved status before downloading a
   DOCX/XLSX/PPTX, saving a PDF, or publishing code. Owners/admins can restore saved
   uploaded-file versions after Office editors close.

In-app **Help & getting started** explains these paths, permissions and unavailable
services. It is accessible on desktop and mobile.

## Current boundaries

New documents and public repository copies work locally. Original-layout upload
editing, private GitHub access/publishing and terminal execution require their
configured services. Native documents do not have saved-version rollback history.
Email delivery, verification and password recovery still need a production
account/email workflow before a public customer launch. No paid service was purchased.
